Projet

Une suite d'outils
pour une équipe de gestion

Le problème n'était pas l'absence de données, mais leur dispersion. Une même question demandait trois systèmes, deux exports et un tableur intermédiaire.

python api sql serveur mcp interface web

Le point de départ

Les positions vivaient dans un système, les valeurs liquidatives dans un autre, les indices de référence chez un fournisseur, les données extra-financières ailleurs encore, et les actualités nulle part en particulier. Chaque question un peu transversale se payait en manipulations manuelles, avec le risque d'erreur que ça implique et, plus grave, une réponse impossible à refaire à l'identique.

Une couche d'accès par domaine

Plutôt qu'un entrepôt monolithique, l'architecture retenue est une couche d'accès découpée par domaine métier : portefeuilles, performance, données de marché, extra-financier, actualités. Chaque domaine expose un petit nombre de fonctions au vocabulaire du métier, et se charge lui-même de savoir où la donnée se trouve réellement.

L'intérêt est moins technique qu'organisationnel : quand la source d'un domaine change, un seul endroit bouge, et rien de ce qui est au-dessus n'a besoin d'être réécrit.

Deux façons de s'en servir

Au-dessus de cette couche, une interface web donne les vues habituelles, portefeuilles, performances, comparaisons. Mais la partie qui a le plus changé les usages est ailleurs : les mêmes fonctions sont exposées à des agents LLM via un serveur MCP.

Concrètement, une question posée en langage naturel déclenche des appels à ces fonctions et revient avec un chiffre sourcé, accompagné du chemin qui a permis de l'obtenir. Le modèle choisit les outils et rédige, il ne produit jamais les nombres lui-même.

C'est le principe qui rend l'ensemble utilisable en contexte professionnel : tout chiffre affiché est traçable jusqu'à sa source, et reproductible à l'identique.

Ce que ça change

Les questions qui demandaient une demi-journée de préparation se posent maintenant à voix haute. Surtout, les questions qu'on ne posait pas, parce que le coût de la réponse dépassait l'intérêt de la savoir, redeviennent accessibles.
